# فحص Spot Testnet المسبق في M1

الفحص المسبق قرائي ومحدود، وليس تنفيذ أمر أو إثبات جاهزية تداول.
يجلب الخادم exchangeInfo حديثًا من Testnet نفسه، لا من العميل،
قبل التحقق الثابت وقبل اختبار الأمر الموقّع.
هذه الدفعة لا تفتح LIVE ولا محرك مطابقة Testnet.

## ما يطبقه الفحص

قواعد الكمية والسعر تشمل LOT_SIZE وMARKET_LOT_SIZE وPRICE_FILTER،
وبالنسبة إلى LIMIT تشمل MIN_NOTIONAL وNOTIONAL، وفق
[توثيق فلاتر Binance](https://developers.binance.com/en/docs/products/spot/filters).
حساب القيمة الاسمية لـLIMIT هو السعر × الكمية، ويُفحص الحد الأدنى
والأقصى والخطوة دون تقريب الكمية أو السعر نيابة عن المستخدم.
يستخدم التنفيذ المحلي Decimal وسياق دقة مستقلًا.

الرمز يجب أن يطابق السجل الوحيد المطلوب، وتكون الحالة TRADING
والتداول Spot متاحًا ونوع الأمر مدعومًا.
المعلومات المفقودة أو المشوهة أو المكررة أو نوع فلتر غير معروف
تُرفض بدل التخمين. مدخلات LIMIT يجب أن تحتوي السعر وtime-in-force؛
MARKET يرفض السعر وtime-in-force.
في مسارات API يجب أن يطابق سعر LIMIT سعر دخول الإشارة حتى لا
تُفحص مستويات خطر لإشارة مختلفة عن السعر المطلوب.

## ما لا يثبته

مرجع السعر/متوسط الصفقات لفلاتر PERCENT_PRICE وPERCENT_PRICE_BY_SIDE
وقيمة MARKET الاسمية ليست سعر الدخول الذي يكتبه المستخدم،
وفق [وثائق Binance](https://developers.binance.com/en/docs/products/spot/filters).
لذلك لا نختلق قيمة MARKET من الإشارة، بل نعرض الفحص المؤجل
`exchange_reference_price_required`.

عدادات الأوامر والمراكز الفعلية والفلاتر الخاصة بالحساب والأصول
والرصيد والصلاحيات لا تُعتمد محليًا.
التقرير يصرح بـ`exchange_validation_required=true`
و`account_and_asset_filters_verified=false`.
حتى نجاح الفحص الثابت لا يمنح إذن تنفيذ أو علامة جاهزية إنتاج.

## مسار API القرائي

`POST /v1/binance/spot/preflight` يتطلب Token وصلاحية `control:read`.
حساب VIEWER يمكنه استخدامه. لا يقرأ مفاتيح BINANCE من البيئة،
ولا يضع أمرًا، ولا يثق بفلاتر أو URL يرسلها العميل.
تُرفض الحقول الخارجية الإضافية.

مثال جسم الطلب:

```json
{
  "signal": {
    "symbol": "BTCUSDT",
    "side": "LONG",
    "entry": 100,
    "stop_loss": 90,
    "take_profit": 120,
    "score": 90,
    "rr": 2,
    "source": "MANUAL",
    "mode": "TESTNET",
    "signal_id": "testnet-preflight-example-001"
  },
  "order_type": "LIMIT",
  "quantity": "0.1",
  "price": "100",
  "time_in_force": "GTC"
}
```

الأرقام مثال برمجي فقط، لا سعر BTC واقعي ولا توصية.
قد ترفض القواعد الحقيقية هذا الطلب؛ الرفض نتيجة صحيحة لا سبب
لتغيير الأسعار أو تقريب القيم تلقائيًا.
التقرير يتضمن الفلاتر التي فُحصت والمؤجلة وhash للمعلومات ووقت الفحص.
فشل البيانات الخارجية يعيد سببًا عامًا دون جسم خطأ البورصة أو أسرار.

## أداة قرائية على خادم مسموح له

بعد إعداد Backend، من مجلده:

```bash
python -m app.testnet_probe --symbol BTCUSDT --quantity 0.1 \
  --price 100 --time-in-force GTC
```

لا يحمّل هذا الأمر مفاتيح ولا يوقّع طلبًا ولا يرسل أمرًا.
الخروج 0 نجاح ثابت محدود، و2 رفض القواعد، و3 تعذر البيانات.
لـMARKET استخدم `--type MARKET` ودون price أو time-in-force.
لا يستخدم CLI إشارة أو يفحص أداء استراتيجية أو صلاحية تنفيذ؛
بوابة الإشارة والإيقاف والصلاحيات تقع في API.

## اختبار الأمر الموقّع

`POST /v1/binance/spot/order-test` يبقى ADMIN عبر `control:write`،
ويجري بوابة الإشارة والإيقاف ثم فحص البيانات الثابتة قبل الطلب الموقّع.
يُعاد فحص الإيقاف بعد جلب البيانات، ولا يصل طلب مرفوض إلى POST.
المسار الوحيد هو `/api/v3/order/test` على Testnet، الذي يختبر إنشاء
الأمر والتوقيع ولا يرسله لمحرك المطابقة وفق
[توثيق Testnet الرسمي](https://developers.binance.com/en/docs/products/spot/testnet/rest-api).
ليس له صلاحية فتح `/api/v3/order` الحقيقي.

المفاتيح مطلوبة لهذه الخطوة وحدها وتوضع على Backend الخاص خارج Git،
ولا ترسل في المحادثة أو المتصفح أو سجل الأخطاء.
لم يُنفذ اختبار موقّع بمفاتيح حقيقية في هذه الدفعة.

## عائق الشبكة والجاهزية

جلب exchangeInfo العام من بيئة التسليم أعاد HTTP 451 برسالة
عدم الإتاحة من موقع مقيد. لم تُجرَ محاولات لتغيير النطاق أو الشبكة
أو التحايل على الأهلية. هذا ليس نقصًا تصلحه مفاتيح API.
استخدم فقط خدمة وحسابًا وشبكة مسموحًا بها قانونيًا ووفق شروط المزود،
أو مزودًا بديلًا مؤهلًا لك.

اختباراتنا بوحدات نقل معزولة لا تثبت توفر Binance الحقيقي.
تبقى مراجعة مستقلة، وحساب Testnet مسموح ومصادق، واختبار الانقطاع
والاستعادة الديناميكية، وIP والصلاحيات، والنشر الإنتاجي متطلبات لاحقة.
