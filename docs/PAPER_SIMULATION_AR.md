# محاكاة PAPER في M1

هذا حساب افتراضي نقدي مقوّم بـUSDT، وليس حساب بورصة أو مالًا حقيقيًا.
المحاكي لا يستورد عميل تنفيذ بورصة ولا يرسل طلب تنفيذ خارجي.
الأسعار والفرق السعري والانزلاق مدخلات مفترضة يحددها المستخدم.
شموع DEMO وبيانات الرسم لا تحدد سعر التعبئة في المحاكي.

## استخدام الواجهة

سجل الدخول من لوحة التحكم، ثم افتح «محاكاة PAPER».
يمكن لـVIEWER عرض حسابه وسجله، ولـOPERATOR أو ADMIN تقديم أوامر افتراضية.
كل مستخدم يرى حسابه فقط؛ حساب ADMIN لا يكشف محافظ الآخرين عبر هذه المسارات.
مثال الشراء والبيع في الواجهة لا يرسل شيئًا حتى تضغط زر المحاكاة.

عند الطلب استخدم `client_order_id` فريدًا. إعادة نفس المعرف مع نفس
المحتوى تعيد الإيصال دون تعبئة جديدة؛ تغيير المحتوى مع نفس المعرف ينتج
409. إعادة إيصال سابق لا تغيّر الرصيد حتى عندما يكون الإيقاف مفعّلًا.
بعد تغيير صلاحيات الأدوار في هذه النسخة، سجل الخروج ثم الدخول للحصول
على `paper:read` و`paper:write` بحسب دورك.

## مسارات API

- `GET /v1/paper/account`: رصيد ومراكز وتكاليف ورسوم وربح/خسارة محققة
  وآخر 20 إيصالًا وحدود الخادم.
- `POST /v1/paper/orders`: شراء أو بيع محاكى، مع Token وصلاحية كتابة.
- `GET /v1/paper/ledger.csv?limit=1000`: سجل المستخدم الخاص؛ 1 إلى 5000
  إيصال، الأحدث أولًا. الحقول النصية محمية من صيغ جداول البيانات.

مثال شراء نقدي:

```json
{
  "mode": "PAPER",
  "client_order_id": "paper-example-buy-001",
  "symbol": "BTCUSDT",
  "side": "BUY",
  "quantity": "1",
  "price": "100",
  "stop_loss": "90",
  "take_profit": "125",
  "score": 90,
  "spread_bps": "0",
  "slippage_bps": "0"
}
```

ليس هذا سعرًا واقعيًا لـBTC أو توصية استثمارية؛ أرقام اختبار حسابية فقط.
لإغلاق المثال أرسل SELL بالكمية نفسها والسعر المفترض 110 ومعرف جديد.
برسوم افتراضية 10 bps يكون النقد النهائي 10009.79 والربح المحقق 9.79،
بعد رسوم شراء 0.10 ورسوم بيع 0.11.

## حدود الخادم

الإعدادات من البيئة ولا يقبل API أن يغيّرها العميل:

| المتغير | الافتراضي |
|---|---|
| `M1_PAPER_INITIAL_CASH` | 10000 USDT افتراضية |
| `M1_PAPER_FEE_BPS` | 10 لكل تعبئة |
| `M1_PAPER_MAX_NOTIONAL` | 1000 لكل دخول |
| `M1_PAPER_MAX_TRADE_RISK_PCT` | 1% |
| `M1_PAPER_MAX_OPEN_RISK_PCT` | 3% |
| `M1_PAPER_MAX_DAILY_LOSS_PCT` | 5% |

يُحفظ الرصيد الابتدائي عند أول تعبئة مقبولة، ولا يتغير بإعادة التشغيل
أو تغيير الإعدادات. GET لا ينشئ حسابًا ماليًا.
حد المراكز خمسة رموز. لا اقتراض أو رافعة أو بيع مكشوف.
يجب أن توجد كمية مملوكة للبيع، وأن يغطي النقد الشراء والرسوم.

يفحص الشراء score وRR والفرق والانزلاق وخسارة اليوم UTC وخطر المحفظة
والقيمة الاسمية والإيقاف، ويحسب المخاطر من السجل المحفوظ لا من قرار العميل.
خسائر اليوم المحققة لا تُمحى بأرباح لاحقة؛ المقام هو الرصيد الابتدائي.
RR وخطر الوقف المخطط يشملان رسوم الدخول والخروج المفترضة.
البيع لتقليل مركز لا تمنعه ميزانية خسائر الدخول، لكن مفتاح الإيقاف
يمنع كل تعبئة جديدة بما فيها البيع. الإيقاف لا يصفّي المراكز تلقائيًا.

## افتراضات لا يجوز تجاهلها

سعر الشراء = السعر المفترض × (1 + (الانزلاق + نصف الفرق) / 10000).
سعر البيع يستخدم العامل المقابل بالطرح. الأرقام محفوظة باستخدام Decimal،
لا أرصدة binary floating-point. متوسط التكلفة يشمل رسوم الشراء.
التقييم `equity_at_cost` تكلفة، وليس mark-to-market.

الوقف والهدف بيانات تخطيط لا أوامر تلقائية ولا ضمان لسعر خروج.
لا دفتر أوامر، ولا تعبئة جزئية سوقية أو زمن انتظار أو funding،
ولا filters/precision موثقة من البورصة. score مجرد افتراض إدخال، لا
تقييم أداء استراتيجية. الرصيد لا يثبت ربحية مستقبلية.

## الاستعادة والعزل

الطلب المقبول يحفظ الحساب والمركز والإيصال والتدقيق في معاملة واحدة.
التكرار المتزامن لا يُعبّأ مرتين ولا ينفق الرصيد مرتين.
قاعدة SQLite نفسها تحمل الجلسات والإيقاف وحسابات المحاكاة.
النسخ والاستعادة يحفظان PAPER؛ الاستعادة تبطل الدخول وتفعّل الإيقاف.
لا توجد إعادة ضبط للحساب من المتصفح؛ استخدم قاعدة منفصلة للاختبارات،
ولا تحذف بيانات تشغيل لتغيير الأرصدة.

## الجاهزية

هذا المحاكي قابل للتجربة والتحقق محليًا ضمن الحدود المذكورة.
ليس تداولًا حقيقيًا مكتملًا ولا تكامل Testnet مصادقًا عليه.
تبقى LIVE ومحولات التنفيذ غير المكتملة مغلقة حتى اعتماد أمان
وتكامل خارجي ونشر تشغيلي مستقل.
